# Проверка (чек-листы)

## Автоматически (запускает Claude)

- `node --test` (или `npm test`) — чистая логика сайта и Apps Script, рекомендации, соответствие `catalog.sample.json` контракту. Папку не указывать: `node --test tests/` в Node 22 не работает.
- Сквозные сценарии: `catalog.e2e.mjs` (каталог, степпер, кэш, безопасный вывод), `order.e2e.mjs` (корзина, форма, «Готово», ошибки; использует поддельный бэкенд из `helpers.mjs`), `layout.e2e.mjs` (все экраны на 360, 390 и 430 px, в том числе с «тяжёлыми» данными: переполнение, обрезанный текст, разорванные слова, зоны нажатия ≥ 48 px, подписи, шрифт ≥ 16 px, заголовки).
- `node tests/e2e/<имя>.e2e.mjs [папка для скриншотов]` — проверки в браузере. Статический сервер для `site/` поднимается сам (`tests/e2e/helpers.mjs`). Файлы `*.e2e.mjs` не входят в `node --test`.
- Playwright, вьюпорт 390×844 (и 360×740 для узких экранов), Chromium `/opt/pw-browsers/chromium`, режим заглушки (`API_URL = ''`):
  - главная → категория → добавить 3 товара → корзина → оформление → «Готово»;
  - пустая корзина; товар 18+ требует галочку; неверный телефон подсвечивается;
  - скриншоты всех экранов (в scratchpad) — посмотреть глазами на переполнение и обрезку текста;
  - в консоли браузера нет ошибок.

## Вручную после каждого развертывания Apps Script (владелец, 2 минуты)

1. `<API_URL>?action=ping` → `{"ok":true,…}`.
2. Сайт открывается, цены совпадают с таблицей.
3. Тестовый заказ с телефоном `+84 000 000 000` и комментарием «ТЕСТ» → строка в «Заказах», сообщение в Telegram. Потом поставить статус «Отменён».

## Перед запуском на гостях (этап 5)

| Проверка | Как |
|---|---|
| iPhone (Safari) и Android (Chrome) | Пройти полный заказ на обоих |
| Российская SIM в роуминге | Сайт открывается, фото грузятся, заказ уходит |
| Медленный интернет | В Chrome DevTools → Network → Slow 4G: главная показывается из кэша, спиннеры понятные |
| Повторное нажатие «Отправить» | Только один заказ в таблице |
| Нет интернета в момент отправки | Экран ошибки + кнопка «Отправить через WhatsApp» с текстом заказа |
| Цена поменялась в таблице | Через ≤ 5 мин на сайте новая; «Обновить сайт сейчас» — сразу |
| Товар выключен, пока он в корзине | Корзина помечает его как недоступный; сервер отклоняет с `ITEM_UNAVAILABLE` |
| `orders_enabled` выключен | Каталог виден, заказать нельзя, есть кнопки связи |
| Кривые данные в таблице | Пустая цена, дубль ID, текст в цене → строка пропущена, сайт работает, в «Ошибках» запись |
| Ввод `=HYPERLINK(...)` в комментарий | В таблице сохраняется как текст, не как формула |
| Ввод `<b>` в имя | В Telegram показывается как текст |
| Доступность | Масштаб текста 200 % в настройках телефона — вёрстка не ломается |
| Ссылка в мессенджере | Переслать ссылку в WhatsApp/Telegram — превью с названием и картинкой |

## Lighthouse и axe

Скрипты `tools/run-lighthouse.mjs` и `tools/run-axe.mjs` (зависимости ставятся во временную папку, в репозиторий не входят; как запускать — в шапке файлов). Результаты на момент T1.5 (мобильный режим, локальный сервер, медиана из 3 прогонов):

| Экран | Производительность | Доступность | Лучшие практики | SEO | LCP |
|---|---|---|---|---|---|
| главная, категория, товар | 100 | 100 | 100 | 63* | 1,7–1,8 с |
| корзина, оформление, «Готово» | 99–100 | 100 | 100 | 60* | 1,8–2,0 с |

\* SEO ниже 100 только из-за `<meta name="robots" content="noindex">` (так задумано). Без этого метатега проверено: 100.

axe-core (WCAG 2.2 A/AA и рекомендации) на всех экранах с заполненной корзиной при 360 и 430 px: нарушений нет. Приёмка T1.5 — доступность ≥ 95, производительность ≥ 90 — выполнена. На живом сайте метрики нужно перемерить после публикации (особенно на медленной сети и с российской SIM, см. этап 5).
