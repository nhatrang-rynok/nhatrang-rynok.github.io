## Потоки данных

### Загрузка каталога

1. Сайт сразу рисует каталог из `localStorage` (если он там есть и не старше 7 дней).
2. Параллельно делает `GET ?action=catalog`.
3. Apps Script отдаёт JSON из CacheService (TTL 5 минут). Если кэша нет — читает листы, собирает JSON, кладёт в кэш.
4. Сайт сравнивает `version` и, если изменилась, перерисовывает экран без мигания. Корзину сверяет с каталогом: пропавшие товары помечает «недоступен», цены обновляет.

### Отправка заказа

1. Сайт отправляет `POST` с `Content-Type: text/plain;charset=utf-8`. Тело — JSON. Такой запрос не требует CORS preflight, а Apps Script его принимает.
2. Сервер под `LockService`:
   - проверяет ловушку, лимиты частоты и идемпотентность (`clientOrderId` в CacheService на 6 ч);
   - валидирует поля, пересчитывает цены по таблице;
   - присваивает номер `N-0001…` (счётчик в Script Properties);
   - пишет строку в «Заказы» и строки в «Позиции заказов».
3. Снимает блокировку, отправляет уведомление в Telegram. Ошибка уведомления заказ не отменяет: пишем в «Ошибки» и шлём письмо.
4. Возвращает `{ok:true, orderNo}`.

### Правка каталога Саней

- Саня правит лист «Товары» → установленный триггер `onEdit` сбрасывает кэш каталога и проставляет «Обновлено».
- Фото: Саня кладёт файл в папку «Фото товаров» на Диске, имя = ID товара (`fr-001.jpg`). Триггер раз в 10 минут (и пункт меню) находит новые файлы, открывает к ним доступ по ссылке и вписывает ID файла в колонку `фото`.

## Изображения

- Основной вариант: `https://lh3.googleusercontent.com/d/<FILE_ID>=w600` (для карточки в списке — `=w400`, на экране товара — `=w900`). Файл должен быть доступен «всем, у кого есть ссылка».
- На сайте: `loading="lazy"`, фиксированное соотношение 1:1 (без прыжков вёрстки), при ошибке загрузки — `img/placeholder.svg`.
- **Запасной план**, если ссылки Диска перестанут работать или будут блокироваться: GitHub Action по расписанию забирает фото через опубликованный эндпоинт `?action=photos` (список ID) и складывает уменьшенные копии в `site/img/products/`. В MVP не делаем — только если понадобится.

## Безопасность и приватность

- Веб-приложение доступно «всем», поэтому любые входные данные считаем враждебными: ограничения длины, белый список полей, экранирование HTML в Telegram-сообщении, защита от формул в ячейках (значения, начинающиеся с `=`, `+`, `-`, `@`, сохраняем с префиксом `'`).
- `doGet` отдаёт только публичные данные: активные товары, категории, публичные настройки. Заказы наружу не отдаются никогда.
- Секреты — только в Script Properties.
- Таблица и папка с заказами доступны только владельцу и Сане. Публичный доступ по ссылке — только у папки с фото.
- Лимиты: не больше 3 заказов с одного телефона за 10 минут, не больше 60 заказов в час всего. Сверх лимита — ошибка `RATE_LIMIT` с текстом «Слишком много заказов, напишите нам в WhatsApp».

## Риски доступности

- Гости с российскими SIM в роуминге выходят в интернет через российского оператора, поэтому к ним применяются российские блокировки и замедления. GitHub Pages, `script.google.com` и `googleusercontent.com` на момент планирования обычно открываются, но это **нужно проверить на этапе 5** с телефона с российской SIM в роуминге. Если что-то из этого не открывается — есть запасной план для фото (выше) и свой домен для сайта.
