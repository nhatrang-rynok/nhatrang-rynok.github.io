# Хостинг и адрес сайта без ника на GitHub

## Проблема

Сайт на GitHub Pages из личного репозитория получает адрес `https://ilyaskvortsov683-wq.github.io/cheap_products/`: в нём ник владельца и название `cheap_products` («дешёвые товары»). Нужен нейтральный адрес.

## Варианты

| Вариант | Адрес | Цена | Плюсы | Минусы |
|---|---|---|---|---|
| **А. Организация на GitHub** | `https://<имя-орг>.github.io/` | 0 ₽ | Тот же GitHub и тот же деплой. Имя выбираешь сам | В публичном репозитории видна история коммитов (ник там есть). Гости туда не заходят, но кто захочет — найдёт |
| **Б. Свой домен** | `https://rynok-nt.ru` или подобный | Обычно от нескольких сотен рублей в год, зависит от зоны | Самый красивый и запоминающийся. Не зависит от хостинга: можно переехать, не меняя адрес. Поверх А или В | Нужно купить и продлевать. Настройка DNS (делается в браузере, один раз) |
| **В. Cloudflare Pages** | `https://<имя>.pages.dev` | 0 ₽ | Репозиторий можно сделать приватным — ника не видно нигде | Россия с 2025 года замедляет и блокирует часть ресурсов на Cloudflare. Гости с российской SIM в роуминге могут не открыть сайт. **Не рекомендую как основной** |
| Г. Netlify / Vercel | `<имя>.netlify.app` / `.vercel.app` | 0 ₽ | Тоже приватный репозиторий | Лишний сервис. Доступность из РФ тоже нужно проверять |
| Д. Сайт прямо на Apps Script | `script.google.com/macros/s/AKfy…/exec` | 0 ₽ | Без GitHub | Длинный некрасивый адрес, плашка Google «приложение создано другим пользователем», медленно. Отклонено |

## Рекомендация

**Сейчас — вариант А (организация), потом при желании — Б (свой домен) поверх него.**

- `<имя-орг>.github.io` без пути выглядит как обычный сайт. Например: `nhatrang-rynok.github.io`, `rynok-u-otelya.github.io`, `nt-market.github.io`. Имя должно быть свободно на GitHub; проверяется при создании.
- Если позже купить домен, он подключается в настройках Pages за 5 минут, а старый адрес будет перенаправлять на новый.
- QR-код для листовок лучше печатать **после** решения про домен, чтобы не перепечатывать.

## Как сделать вариант А (всё в браузере)

1. **Создать организацию.** github.com → «+» справа вверху → **New organization** → план **Free** → имя организации (оно и будет в адресе), почта → «This organization belongs to: My personal account» → Next. Пропусти приглашение участников.
2. **Скрыть членство.** Организация → **People** → у себя: **Organization visibility: Private** (обычно так по умолчанию — проверь). Тогда на странице организации не видно, кто в ней состоит.
3. **Перенести репозиторий.** Репозиторий `cheap_products` → **Settings → General** → внизу **Danger Zone → Transfer ownership** → выбрать организацию → подтвердить.
4. **Переименовать репозиторий** в `<имя-орг>.github.io` (точно так, строчными буквами). **Settings → General → Repository name**. Тогда сайт будет в корне `https://<имя-орг>.github.io/`, без пути. GitHub сам перенаправит старые ссылки на репозиторий.
5. **Дать Claude доступ к организации.** Установить приложение Claude на организацию: https://github.com/apps/claude/installations/select_target → выбрать организацию → доступ к этому репозиторию. Если сессии Claude Code перестали видеть репозиторий — переподключить GitHub в claude.ai (Settings → Connectors / GitHub).
6. **Включить Pages.** Репозиторий → **Settings → Pages** → **Source: GitHub Actions**. Сам workflow (`.github/workflows/pages.yml`) напишет Claude в задаче T1.1.
7. Сообщить новое имя репозитория в сессию Claude Code. Дальше Claude работает с новым адресом.

> Шаги 3–4 удобнее сделать **до начала кода** (этап 0), пока нет ссылок, которые придётся менять.

### Что с ником в истории коммитов

В публичном репозитории история коммитов показывает автора. Если это важно:
- в настройках GitHub включить **Settings → Emails → «Keep my email addresses private»** — скроет почту, но не ник;
- полностью скрыть ник можно только приватным репозиторием. Для GitHub Pages из приватного репозитория организации нужен платный план — тогда проще вариант В, но с риском доступности из РФ.

Для задачи «гость не видит ник в ссылке» достаточно варианта А.

## Как сделать вариант Б (свой домен), когда понадобится

1. Купить домен у регистратора (для `.ru` — любой российский регистратор, для `.com` — любой международный). Имя — короткое и понятное на слух, латиницей, например `rynok-nt.ru`.
2. В панели регистратора добавить DNS-запись: **CNAME** `www` → `<имя-орг>.github.io`, и для корня — четыре **A**-записи на IP GitHub Pages (актуальный список — в документации GitHub Pages, раздел «Managing a custom domain»).
3. Репозиторий → **Settings → Pages → Custom domain** → ввести домен → Save → дождаться проверки → включить **Enforce HTTPS**.
4. Сказать Claude, чтобы обновил ссылки в документации и Open Graph метатегах.

## Проверка доступности (этап 5)

Открыть сайт и `?action=ping` Apps Script с телефона:
- на Wi-Fi отеля;
- на вьетнамской SIM;
- на **российской SIM в роуминге** — обязательно, это самый рискованный случай;
- проверить, что грузятся фото (`lh3.googleusercontent.com`).
