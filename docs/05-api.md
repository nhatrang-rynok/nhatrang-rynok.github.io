# Контракт API: сайт ↔ Apps Script

Базовый URL — адрес веб-приложения Apps Script (`https://script.google.com/macros/s/<DEPLOYMENT_ID>/exec`). Хранится в `site/config.js` как `API_URL`. Пустая строка — режим заглушки.

Все ответы — JSON (`ContentService`, MIME `application/json`). Apps Script всегда отвечает HTTP 200 (по-другому он не умеет), поэтому успех определяется полем `ok`.

## GET `?action=catalog`

Публичный каталог.

```json
{
  "ok": true,
  "version": "2026-10-10T14:03:22Z#a1b2c3",
  "generatedAt": "2026-10-10T14:03:22Z",
  "settings": {
    "site_title": "Рынок у отеля",
    "phone": "+84 000 000 000",
    "whatsapp": "84000000000",
    "telegram": "primer_operator",
    "orders_enabled": true,
    "log_events": true,
    "announcement": "",
    "terms": "",
    "done_text": "С вами свяжутся по поводу заказа на оставленный контактный телефон. Ожидайте."
  },
  "categories": [
    { "id": "fruits", "name": "Фрукты", "icon": "🥭", "note": "", "sort": 1 }
  ],
  "products": [
    {
      "id": "fr-001",
      "cat": "fruits",
      "name": "Манго",
      "short": "Сладкое, спелое",
      "desc": "…",
      "price": 90,
      "vnd": 27000,
      "usd": 1.08,
      "pw": 300,
      "unit": "кг",
      "step": 0.5,
      "min": 1,
      "img": "https://lh3.googleusercontent.com/d/FILE_ID",
      "warn": "Сок и кожура могут вызвать раздражение кожи…",
      "src": "Рынок Чо Дам",
      "adult": false,
      "stock": "in",
      "rel": ["fr-002", "sw-001"],
      "sort": 10
    }
  ],
  "popular": ["fr-001", "al-002"]
}
```

Правила:
- `version` меняется при любом изменении данных (время сборки + короткий хэш содержимого).
- `img` — базовая ссылка **без** суффикса размера, сайт добавляет `=w400` / `=w900` сам. Пусто — сайт показывает заглушку.
- `stock`: `in` | `preorder` | `out`. Товары с `out` отдаются (показываем серыми), выключенные (`Показывать` снят) — не отдаются.
- `vnd` — цена за единицу в донгах («Цена ₫», а если её нет — рубли × курс), `usd` — она же в долларах по курсу `rate_vnd_per_usd` (до центов), `pw` — вес одной штуки в граммах («Вес 1 шт., г», 0 — не задан). Сайт только показывает их, считает сервер. Курсы наружу не отдаются.
- `popular` — ID в порядке показа: сначала «Хит», потом по статистике за `popular_days`, всего не больше `popular_count`. Только товары со `stock` ≠ `out`.
- `whatsapp` отдаётся уже очищенным (только цифры) — для ссылок `https://wa.me/<цифры>`.
- Ошибка: `{ "ok": false, "error": "SERVER", "message": "…" }`.

`site/data/catalog.sample.json` должен строго соответствовать этому формату. Тест `tests/sample-catalog.test.js` это проверяет.

## POST — заказ

Запрос: `Content-Type: text/plain;charset=utf-8` (не `application/json` — иначе браузер отправит preflight, который Apps Script не обрабатывает). Тело — JSON:

```json
{
  "action": "order",
  "clientOrderId": "c0f7e6a2-1b3c-4d5e-9f00-123456789abc",
  "phone": "+7 (999) 000-00-00",
  "messenger": "whatsapp",
  "name": "Ольга",
  "room": "512",
  "comment": "Манго поспелее",
  "items": [
    { "id": "fr-001", "qty": 2 },
    { "id": "al-002", "qty": 1 }
  ],
  "clientTotal": 830,
  "catalogVersion": "2026-10-10T14:03:22Z#a1b2c3",
  "visitorId": "v1x9k2m0q8z7a6b5c4d3",
  "website": ""
}
```

- `messenger`: `whatsapp` | `telegram` | `call`.
- `website` — поле-ловушка. Если не пустое, сервер отвечает **успехом** с фиктивным номером и ничего не сохраняет.
- `clientTotal` и `catalogVersion` — только для диагностики, сервер их не использует для расчёта.
- `visitorId` — случайный номер браузера (8–64 знака `[A-Za-z0-9_-]`), нужен только для листа «Журнал». Необязателен; неверный формат молча отбрасывается.

### Ответ: успех

```json
{ "ok": true, "orderNo": "N-0042", "total": 830, "duplicate": false }
```

`duplicate: true` — такой `clientOrderId` уже был, возвращён прежний номер.

### Ответ: ошибка

```json
{
  "ok": false,
  "error": "ITEM_UNAVAILABLE",
  "message": "Некоторые товары сейчас недоступны",
  "fields": {},
  "items": ["fr-003"]
}
```

| `error` | Когда | Что делает сайт |
|---|---|---|
| `VALIDATION` | Неверный телефон, слишком длинные поля, пустая корзина, нет галочки 18+, неверное количество | Подсвечивает поля из `fields` (`{"phone": "Проверьте номер"}`) |
| `ITEM_UNAVAILABLE` | Товара нет, он выключен или `stock = out` | Убирает `items` из корзины, показывает, что именно убрано, предлагает отправить снова |
| `ORDERS_PAUSED` | `orders_enabled` = выкл | Показывает объявление и кнопки связи |
| `RATE_LIMIT` | Превышены лимиты | «Слишком много заказов подряд. Напишите нам в WhatsApp» + кнопка |
| `SERVER` | Всё остальное | Экран ошибки с «Повторить» и «Отправить через WhatsApp» |

Сетевая ошибка или таймаут (15 с) обрабатываются как `SERVER`. При повторе отправляется **тот же** `clientOrderId`.

### Серверная валидация

- `phone`: убрать всё, кроме цифр и ведущего `+`; `8XXXXXXXXXX` (11 цифр, начинается с 8) → `+7XXXXXXXXXX`; без `+` → добавить `+`; итог `^\+\d{9,15}$`.
- На сайте проверка телефона чуть строже: 10 цифр, начиная с 9, без «+» (российский номер без кода страны) не принимается с подсказкой «Добавьте код страны». Сервер (`Logic.gs`, `checkPhone_`) делает так же, это проверяется тестом на совпадение с сайтом. Префикс `00` (международный) заменяется на «+».
- Поле-ловушка в форме называется `hp-check` (не `website`, чтобы автозаполнение браузера его не трогало), а в запрос уходит как `website`.
- `name` ≤ 50, `room` ≤ 10, `comment` ≤ 500 символов. Управляющие символы заменяются пробелом (в комментарии переносы строк остаются); слишком длинное значение — `VALIDATION` с текстом у поля, а не молчаливая обрезка.
- `clientOrderId` — строка из 8–64 знаков `[A-Za-z0-9_-]` (UUID или запасной формат сайта); иначе `VALIDATION`.
- `messenger` — `whatsapp` / `telegram` / `call`; не указан — `whatsapp`; любое другое значение — `VALIDATION`.
- Порядок проверок: поля формы и состав (`VALIDATION`) → недоступные товары (`ITEM_UNAVAILABLE`) → количество по шагу и минимуму и 18+ (`VALIDATION`).
- `items`: от 1 до 50 позиций, ID приводятся к нижнему регистру, уникальны (дубли складываются), `qty` — число > 0, ≤ 100, кратное `step` (погрешность 1e-9), ≥ `min`.
- Подтверждение возраста не требуется (D78): заказывают только взрослые. Поле `adultConfirmed` сервер игнорирует; у заказа с товаром `adult` в таблице стоит отметка «18+ подтверждено», в сообщении Telegram — «🔞 В заказе есть товары 18+».
- Телефон: код любой страны. Нужны 9–15 цифр с кодом; номер без «+» принимается, только если он не из 10 цифр на 9 (так выглядит номер без кода); 11 цифр на 8 без «+» читаются как российский («8 999…» → +7999…).
- Сумма = Σ (цена ₽ из таблицы × qty), округлить до целых рублей.

## GET `?action=orders&ids=<id1,id2,…>`

Статусы заказов для вкладки «Мои заказы» на сайте. `ids` — до 20 `clientOrderId` через запятую (те, что сайт запомнил после успешной отправки). Ответ:

```json
{ "ok": true, "orders": [
  { "id": "…", "found": true, "orderNo": "N-0042", "status": "Закуплено" },
  { "id": "…", "found": false, "orderNo": "", "status": "" }
] }
```

- `status` — значение колонки «Статус» в «Заказах»: `Новый`, `Связались`, `Закуплено`, `Доставлено`, `Отменён` (любое другое читается как `Новый`). Сайт показывает их словами «Принят, скоро свяжемся», «Мы с вами связались», «Куплено, везём», «Доставлен», «Отменён»; `Доставлено` и `Отменён` — завершённые.
- Телефон, имя, комната и состав **не отдаются**. `clientOrderId` — случайный UUID, его знает только тот, кто оформил заказ.

## GET `?action=orderStatus&id=<clientOrderId>`

Принят ли заказ с таким `clientOrderId`. Сайт спрашивает это, когда ответ на POST не дошёл до браузера (на телефоне с Яндекс.Браузером заказ записывался, а гость видел «Не получилось отправить»). Данные берутся из кэша повторных отправок (6 часов).

- Найден: `{ "ok": true, "found": true, "orderNo": "N-0042", "total": 830 }`. Не найден: `{ "ok": true, "found": false }`. Неверный `id`: `VALIDATION`.
- Сайт спрашивает дважды с паузой 2 секунды (сервер мог ещё не дописать). Нашёл — показывает «Заказ принят». Нет — экран ошибки; «Попробовать ещё раз» не создаст дубль (тот же `clientOrderId`).
- В ответе нет телефона, имени и состава. Номер запроса — случайный UUID, его знает только отправитель.

## JSONP: запасной способ чтения GET-ответов

К любому GET-запросу (`ping`, `catalog`, `orderStatus`) можно добавить `&callback=имя` (латиница, цифры, `_`, до 41 знака, не с цифры). Тогда ответом будет скрипт `имя({...});` с типом JavaScript: его читают через `<script src>`, минуя CORS. Нужен для браузеров, где обычный `fetch` к Apps Script запускает скрипт, но ответ прочитать не может. Другое имя функции игнорируется (приходит обычный JSON). Используется страницей `/diag.html`.

## GET `?action=ping`

`{ "ok": true, "time": "…", "version": "2026-10-12.6" }` — проверка, что развертывание живо. `version` — версия кода Apps Script (`SCRIPT_VERSION_` в `Main.gs`): по ней видно, какой код сейчас работает. Используется в инструкции по развертыванию.

## POST — журнал событий сайта

Тот же адрес и тот же `text/plain`. Сайт шлёт пачку событий (`fetch` с `keepalive`, ответ не читает):

```json
{
  "action": "log",
  "visitorId": "v1x9k2m0q8z7a6b5c4d3",
  "now": 1760000000000,
  "device": { "ua": "Mozilla/5.0 (iPhone; …)", "w": 390, "h": 844, "lang": "ru-RU" },
  "events": [
    { "t": 1759999990000, "k": "view", "d": "/c/fruits — Фрукты — Рынок у отеля", "s": "category" },
    { "t": 1759999995000, "k": "click", "d": "кнопка «Добавить в корзину: Манго»", "s": "category", "o": "" }
  ]
}
```

- `now` и `t` — время по часам телефона в миллисекундах. Сервер берёт только разницу («сколько назад») и пересчитывает по своим часам, поэтому неверные часы телефона не портят журнал; события не старше часа.
- `k` — вид события: `visit`, `view`, `click`, `change`, `cart`, `catalog`, `order`, `error`, `session`. Остальные отбрасываются. `d` — подробности (до 200 знаков, длинные числа заменяются на `[номер]`), `s` — имя экрана, `o` — номер заказа (`[A-Za-z0-9-]{1,12}`).
- В пачке до 50 событий. Сайт отправляет не чаще раза в 5 секунд, а также при закрытии или сворачивании вкладки.
- Ответ: `{ "ok": true, "logged": N }`; `disabled: true`, если выключен `log_events`; `limited: true`, если превышен лимит (15 пачек в минуту с посетителя, 3000 в час всего); неверный `visitorId` — `{ "ok": false, "error": "VALIDATION" }`.
- Сайт не отправляет события в режиме заглушки (пустой `API_URL`) и при `settings.log_events === false`.
