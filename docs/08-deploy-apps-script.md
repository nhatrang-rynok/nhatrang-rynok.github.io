# Как развернуть Apps Script (инструкция для владельца)

Всё делается в браузере на компьютере. Командная строка не нужна. Названия пунктов даны для русского интерфейса Google, в скобках — английские.

Код лежит в репозитории, в папке `apps-script/`. Файл в репозитории = файл в редакторе. Открывать файлы на GitHub удобно так: открыть файл → кнопка **«Copy raw file»** (два квадратика над кодом) → вставить в редактор.

> Секреты (токен бота и т. п.) в репозитории не хранятся и в код не вставляются: только в **Свойства скрипта** (шаг «Свойства скрипта» ниже).

## Часть 1. Первая установка кода (T2.3)

### Шаг 1. Открыть редактор

1. Открой таблицу **«Мой рынок»** → **Расширения → Apps Script** (Extensions → Apps Script).
2. Слева вверху можно назвать проект, например «Рынок».
3. Слева ⚙️ **«Настройки проекта»** (Project Settings) → включи **«Показывать файл манифеста appsscript.json в редакторе»**.

### Шаг 2. Заменить файлы проекта

В списке файлов слева сейчас есть `Код.gs` (`Code.gs`) и, возможно, `index` (HTML). Нужно, чтобы остались только файлы из репозитория.

1. **`index`** (HTML-файл): наведи на него → ⋮ → **«Удалить»**. Он не нужен.
2. **`Код.gs`**: ⋮ → **«Переименовать»** → введи `Main` (без `.gs`). Выдели в нём весь текст (Ctrl+A) и вставь содержимое `Main.gs` из репозитория.
3. **`appsscript.json`**: открой, выдели всё, вставь содержимое `apps-script/appsscript.json`.
4. Добавь три файла: **«+» рядом с «Файлы» → «Скрипт»**, имя **без `.gs`**, вставь содержимое:
   - `Logic`
   - `Catalog`
   - `Setup`
5. Нажми 💾 (Ctrl+S). В списке файлов должно быть ровно: `Catalog`, `Logic`, `Main`, `Setup`, `appsscript.json`.

### Шаг 3. Первая настройка таблицы

1. Вверху в выпадающем списке функций выбери **`setup`** → **«Выполнить»** (Run).
2. Появится **«Требуется авторизация»** → **«Проверить разрешения»** → выбери свой аккаунт.
3. Экран **«Приложение не проверено Google»** нормален для своего скрипта: **«Дополнительные настройки» → «Перейти на страницу … (небезопасно)» → «Разрешить»**. Разрешения: таблица, меню, триггеры.
4. Дождись «Выполнение завершено». В таблице появятся листы **Товары, Категории, Настройки, Заказы, Позиции заказов, Ошибки**, пустой «Лист1» исчезнет, а вверху — меню **«🛒 Рынок»**. Появится окно «Настройка завершена» со сводкой (если не появилось, обнови страницу таблицы).

Повторный запуск `setup` безопасен: данные не стираются и не дублируются.

### Шаг 4. Загрузить примеры товаров

Каталог на сайте пока пустой. Загрузим 14 примерных товаров (фрукты и ром), чтобы проверить всю цепочку. Потом вы с Саней замените их настоящими.

1. На GitHub открой `content/descriptions/sample-products.csv` → **«Download raw file»** (значок загрузки справа над кодом). Файл сохранится на компьютер.
2. В таблице открой лист **«Товары»** → **Файл → Импорт → Загрузка** → выбери файл → **«Заменить текущий лист»** → **«Импортировать данные»**. Если таблица спросит про защищённый диапазон (заголовки), подтверди: это только предупреждение.
3. **🛒 Рынок → Первоначальная настройка**: вернёт флажки и выпадающие списки, которые импорт мог сбросить.
4. **🛒 Рынок → Проверить таблицу** → должно быть «Проблем не найдено. На сайте сейчас: товаров — 14, категорий — 2».

Фото у товаров пока нет, на сайте будет заглушка. Фото подключим в задаче T3.1.

### Шаг 5. Свойства скрипта (секреты)

Токен бота ты уже добавил. Проверь, что он на месте: ⚙️ **«Настройки проекта» → «Свойства скрипта»** (Script Properties): должно быть `TELEGRAM_BOT_TOKEN`. Остальные свойства (`TELEGRAM_CHAT_IDS`, `ALERT_EMAIL`) добавляются в части 1б.

### Шаг 6. Обновить веб-приложение (развертывание уже есть)

Веб-приложение у тебя уже развёрнуто, адрес менять не нужно. Нужно только выпустить **новую версию** в нём:

1. **«Начать развертывание» (Deploy) → «Управление развертываниями» (Manage deployments)**.
2. Выбери активное развертывание → ✏️ **карандаш** → **«Версия»: «Новая версия»** → **«Развернуть»**. Если попросит разрешения — разреши.
3. Проверь в браузере (подставь свой адрес, оканчивающийся на `/exec`):
   - `<адрес>?action=ping` → `{"ok":true,"time":"…"}`;
   - `<адрес>?action=catalog` → длинный текст JSON, в котором есть названия товаров («Манго», …).
   Если браузер просит войти в Google, в развертывании не выбрано «У кого есть доступ: Все» (см. ниже «Если что-то не работает»).
4. **Пришли в сессию Claude Code** слова «T2.3 готово» и, если проверка не прошла, текст ошибки или скриншот.

> ⚠️ **Не нажимай «Новое развертывание»** для обновлений: получится новый адрес, и сайт продолжит ходить по старому.
>
> Изменения кода без шага 6 на сайт **не попадают**: веб-приложение работает на зафиксированной версии. Меню и триггеры в таблице при этом сразу используют свежий код.

На сайт каталог и заказы подключаются в задаче T2.6 (адрес впишет Claude), после проверки приёма заказов (часть 1б).

## Часть 1б. Приём заказов и уведомления (T2.5)

### Сначала — где что находится (чтобы не путаться)

У проекта три «места», и тестировать нужно в разных:

| Место | Что это | Что там делать |
|---|---|---|
| **Таблица «Мой рынок»** | Обычная Google Таблица. В верхней строке меню, правее «Справки», есть **«🛒 Рынок»** | Все проверки из этой части: тестовое уведомление, поиск chat_id, тестовый заказ |
| **Редактор Apps Script** | Расширения → Apps Script. Тут лежит код (`Main`, `Logic`, …) и свойства | Вставка кода, свойства, выдача разрешений, запуск функций |
| **Сайт** | `https://nhatrang-rynok.github.io/` | Подключается к серверу в части 1в. **Файл `index.html` в Apps Script не нужен**: тот `index` был заготовкой, мы его удалили. Сайт лежит на GitHub |

**Telegram-бот ничего не отвечает, и это нормально.** Он только *отправляет* сообщения о заказах, разговаривать он не умеет. Ты нажимаешь у него «Старт», а в ответ тишина: так и задумано. «Старт» нужен только для того, чтобы Telegram разрешил боту писать тебе. А chat_id находится не в боте, а в меню таблицы (шаг 3).

### Шаг 1. Обновить файлы

Самая частая ошибка на этом шаге: вставить код одного файла в другой. Поэтому у каждого файла **первая строка комментария называет его имя**, по ней можно проверить.

1. Таблица → **Расширения → Apps Script**. Слева ⚙️ **«Настройки проекта»** → включи **«Показывать файл манифеста appsscript.json в редакторе»** (если ещё не включено).
2. Для каждого файла: открой его в редакторе → выдели всё (Ctrl+A) → вставь свежий код из репозитория → Ctrl+S. Код удобно брать по прямым ссылкам (откроется чистый текст, выдели всё и скопируй):

| Файл в редакторе | Что должно быть в начале (вторая строка) | Ссылка на код |
|---|---|---|
| `Catalog` | ` * Catalog.gs — чтение таблицы…` | https://raw.githubusercontent.com/nhatrang-rynok/nhatrang-rynok.github.io/main/apps-script/Catalog.gs |
| `Journal` | ` * Journal.gs — лист «Журнал»…` | https://raw.githubusercontent.com/nhatrang-rynok/nhatrang-rynok.github.io/main/apps-script/Journal.gs |
| `Logic` | ` * Logic.gs — чистая логика…` | https://raw.githubusercontent.com/nhatrang-rynok/nhatrang-rynok.github.io/main/apps-script/Logic.gs |
| `Main` | ` * Main.gs — точки входа…` | https://raw.githubusercontent.com/nhatrang-rynok/nhatrang-rynok.github.io/main/apps-script/Main.gs |
| `Notify` | ` * Notify.gs — уведомления оператору…` | https://raw.githubusercontent.com/nhatrang-rynok/nhatrang-rynok.github.io/main/apps-script/Notify.gs |
| `Orders` | ` * Orders.gs — приём заказа с сайта…` | https://raw.githubusercontent.com/nhatrang-rynok/nhatrang-rynok.github.io/main/apps-script/Orders.gs |
| `Setup` | ` * Setup.gs — первоначальная настройка…` | https://raw.githubusercontent.com/nhatrang-rynok/nhatrang-rynok.github.io/main/apps-script/Setup.gs |
| `appsscript.json` | `{ "timeZone": …` | https://raw.githubusercontent.com/nhatrang-rynok/nhatrang-rynok.github.io/main/apps-script/appsscript.json |

   Если какого-то файла в списке нет, создай его: **«+» рядом с «Файлы» → «Скрипт»**, имя без `.gs`.
3. **Проверь по таблице выше**, что в каждом файле в начале стоит свой комментарий. В списке слева должно быть ровно семь файлов (`Catalog`, `Journal`, `Logic`, `Main`, `Notify`, `Orders`, `Setup`) плюс манифест.
4. Выпадающий список функций вверху должен содержать `authorize`, `findTelegramChatIds`, `menuTestOrder`, `testNotify`, `setup`.
5. Открой `appsscript.json`, выдели всё и **замени содержимым файла из таблицы выше**. В нём **не должно быть строки `oauthScopes`**: Google сам определит, какие разрешения нужны коду (таблица, запросы в интернет, почта, триггеры). Если в твоём `appsscript.json` остался старый список `oauthScopes`, Google выдаёт только то, что в нём перечислено, и ошибки «нет разрешения на вызов функции UrlFetchApp.fetch / MailApp.sendEmail» не пропадут, а окно разрешений вообще не появится.
6. **Если при запуске любой функции в журнале написано `SyntaxError: Identifier '…' has already been declared`**, значит один и тот же код вставлен в два файла (или лишний файл остался). Имя в сообщении подскажет, чей это код: например, `HEADER_COLOR_` живёт в `Setup`. Открой файл, который назван в ошибке (`… @ Orders.gs:1`), и проверь его начало по таблице выше.

### Шаг 2. Выдать новые разрешения

Окно с разрешениями **не появляется само**: ни при открытии таблицы, ни из меню «🛒 Рынок», ни при вызове с сайта. Оно показывается **только когда запускаешь функцию в редакторе**. Без этого Telegram и почта не работают: ошибки «нет разрешения на вызов функции UrlFetchApp.fetch / MailApp.sendEmail» значат именно это.

1. В редакторе вверху выбери функцию **`authorize`** → **«Выполнить»**.
2. Появится **«Требуется авторизация»** → **«Проверить разрешения»** → выбери свой аккаунт.
3. Экран «Приложение не проверено Google»: **«Дополнительные настройки» → «Перейти на страницу … (небезопасно)» → «Разрешить»**.
4. Функция сама ничего не показывает окном (раньше окно «зависало»): итог смотри **внизу редактора в «Журнале выполнения»** и во всплывающей подсказке в таблице: версия кода, ✅ или ❌ по таблице, запросам в интернет, почте, триггерам и свойствам. Нужно, чтобы первые четыре строки были с ✅. Если ❌ у свойств, это дело шагов 4 и 5.
5. **Если окно с разрешениями не появилось, а ❌ остались**: в редакторе остался старый `appsscript.json` со списком `oauthScopes` (шаг 1, пункт 5). Замени его содержимое и запусти `authorize` снова.
6. Потом в таблице можно проверять разрешения без редактора: **🛒 Рынок → Проверить разрешения** (покажет то же окном, но выдать разрешения оттуда нельзя).

### Шаг 3. Меню «🛒 Рынок»

1. **Обнови страницу с таблицей** (F5). Меню собирается только при открытии таблицы, поэтому после замены кода без обновления страницы старые пункты не меняются.
2. В меню должны быть пункты: Обновить сайт сейчас, Проверить таблицу, **Отправить тестовое уведомление**, **Найти chat_id Telegram**, **Создать тестовый заказ**, **Проверить разрешения**, Первоначальная настройка.
3. **Если меню нет или пунктов не хватает** даже после обновления страницы: в редакторе выбери функцию **`onOpen`** → «Выполнить» (меню появится в открытой таблице). Если пунктов всё равно мало, код `Main` не заменился (шаг 1).
4. **Если меню совсем недоступно** (например, на телефоне), всё из этой части можно запустить прямо из редактора: выбери нужную функцию (`findTelegramChatIds`, `testNotify`, `menuTestOrder`) и нажми «Выполнить». Результат покажется окном в таблице, которая открыта в другой вкладке.

### Шаг 4. Свойства скрипта

⚙️ **«Настройки проекта» → «Свойства скрипта»**. Должны быть:

| Свойство | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота (уже добавлен) |
| `ALERT_EMAIL` | твоя почта: сюда придёт письмо, если Telegram не сработает |
| `TELEGRAM_CHAT_IDS` | заполняется на шаге 5 |

### Шаг 5. Получатели в Telegram

1. **Саня** (и ты, если хочешь получать заказы) открывает бота в Telegram по ссылке и нажимает **«Старт»**. **Бот не ответит**, это нормально.
2. В таблице: **🛒 Рынок → Найти chat_id Telegram**. Появится окно «Боту писали:» со списком людей и их числами (chat_id).
   - Если там «Бот пока никого не видит» — получатель не нажал «Старт» или прошло больше суток. Пусть ещё раз откроет бота, нажмёт «Старт» и напишет любое слово, потом повтори.
   - Если «Telegram не ответил: Conflict… webhook» — к боту подключён другой обработчик; напиши об этом в сессию.
3. Нажми **«Да»**: числа запишутся в свойство `TELEGRAM_CHAT_IDS`. (Хочешь, чтобы заказы приходили только Сане: нажми «Нет» и вручную впиши только его число в свойство.)
4. **🛒 Рынок → Отправить тестовое уведомление** → у каждого получателя в Telegram появится «✅ Проверка связи: уведомления о заказах работают.» Если в окне ❌, там написана причина.

### Шаг 6. Тестовый заказ

1. **🛒 Рынок → Создать тестовый заказ**. Окно покажет номер заказа и «Уведомление: ok». В Telegram придёт сообщение «🛒 Новый заказ …» с кнопками.
2. В листе **«Заказы»** появилась строка (имя «ТЕСТ», статус «Отменён»), в **«Позиции заказов»** одна строка с отметкой «Отменён».
3. **Проверь защиту от формул.** В ячейке «Телефон» должно быть `+84000000000` **без апострофа**. Если виден апостроф `'+84000000000`, напиши в сессию: способ записи нужно будет поменять.
4. В «Свойства скрипта» появилось `ORDER_SEQ`. Тестовый заказ занял N-0001; если хочешь, чтобы первый настоящий заказ тоже был N-0001, удали тестовые строки в «Заказы» и «Позиции заказов» и свойство `ORDER_SEQ`.
5. **Если ты делал тестовые заказы со старой версией кода** (до исправления от 12 октября), они записались в самый низ листов (строки 1001 и ниже), а не в начало. Их нужно удалить, иначе новые заказы тоже будут идти ниже них: в «Заказы» нажми Ctrl+↓ в колонке «Номер», дойдёшь до этих строк, выдели их номера строк слева → правая кнопка → «Удалить строки». То же в «Позиции заказов». Заодно удали свойство `ORDER_SEQ`.

### Шаг 7. Новая версия веб-приложения

**Развернуть → Управление развертываниями → ✏️ → «Версия»: «Новая версия» → «Развернуть»**. Адрес не меняется. Проверь `<адрес>?action=ping`.

Напиши в сессию «T2.5 готово» и результаты шагов 5–6.

## Часть 1г. Журнал событий и разрешения (версия кода 2026-10-12.4)

> Версия `2026-10-12.4` (после `.3`): новые записи в «Журнале» встают сверху; сайт сам проверяет у сервера, принят ли заказ, если ответ на отправку не дошёл до телефона. Заменить в редакторе нужно файлы `Journal`, `Main`, `Orders` (остальные без изменений), затем новая версия веб-приложения.

В таблице появился лист **«Журнал»**: в него сами записываются заходы на сайт, открытые экраны, нажатия, изменения корзины, отправка заказа, запись заказа, отправка уведомлений, правки таблицы и нажатия пунктов меню. В листе **«Ошибки»** время теперь записывается с секундами (раньше была видна только дата), ошибки дублируются в «Журнал».

### Что делать

1. **Замени файлы в редакторе** (ссылки в таблице части 1б, шаг 1): `appsscript.json` (в нём больше нет `oauthScopes`), `Catalog`, `Logic`, `Main`, `Notify`, `Orders`, `Setup` и **новый файл `Journal`** (**«+» рядом с «Файлы» → «Скрипт»**, имя `Journal`). Всего файлов теперь семь плюс манифест.
2. В редакторе выбери функцию **`authorize`** → **«Выполнить»**. Если появилось окно с разрешениями, разреши всё (часть 1б, шаг 2). Итог смотри внизу в «Журнале выполнения»: у первых четырёх пунктов должен быть ✅.
3. В таблице обнови страницу (F5) → **🛒 Рынок → Первоначальная настройка**. Появится лист «Журнал» (он создаётся и сам при первой записи), у «Ошибок», «Заказов» и «Журнала» время получит формат с секундами, в «Настройках» добавится строка `log_events`.
4. **Выпусти новую версию веб-приложения**: Развернуть → Управление развертываниями → ✏️ → «Версия»: «Новая версия» → «Развернуть». Новое развертывание не создавай, адрес не меняется. Проверь `<адрес>?action=ping`: `"version"` должна быть `2026-10-12.4`.
5. Дальше по части 1б: шаг 5 (**Найти chat_id Telegram → Да**), **Отправить тестовое уведомление**, **Создать тестовый заказ**.

### Как читать «Журнал»

| Колонка | Что в ней |
|---|---|
| **Время** | Когда это было (по Нячангу), с секундами. **Новые записи появляются сверху**, под заголовком. Если лист раньше сортировали вручную, ничего менять не нужно: новые строки встанут над старыми |
| **Уровень** | `инфо`, `внимание` (жёлтая строка), `ошибка` (красная строка) |
| **Источник** | `Сайт` (что делал гость в браузере) или `Сервер` (что сделал скрипт) |
| **Событие** | Вход на сайт, Открыт экран, Нажатие, Выбор, Корзина, Каталог (сайт), Заказ (сайт), Выход с сайта, Заказ получен, Заказ записан в таблицу, Telegram: отправлено, Уведомление о заказе, Правка таблицы, Меню: … и так далее |
| **Подробности** | Что именно (какая кнопка, какой товар, куда ушёл заказ, причина ошибки) |
| **Экран** | Где был гость: `home`, `category`, `product`, `cart`, `checkout`, `done` |
| **Посетитель** | Первые 8 знаков случайного номера, который сайт присваивает браузеру. По нему можно отфильтровать всё, что делал один человек (Данные → Создать фильтр). Номер не связан с именем или телефоном |
| **Заказ** | Номер заказа, если событие про заказ (N-0007): так видно путь гостя до заказа |
| **Устройство** | Телефон/браузер/размер экрана/язык, например `iPhone · Safari · 390×844 · ru-RU` |

Чего в журнале **нет**: имени, телефона, комнаты и комментария гостя, текста, который он вводил, токена бота, целых chat_id (только последние 4 цифры).

### Выключить и размер

- В листе **«Настройки»** строка `log_events`: **снять галочку** — сайт перестанет присылать события (серверные записи о заказах и ошибках остаются). Эффект — в течение 5 минут или сразу после «🛒 Рынок → Обновить сайт сейчас».
- Хранится последние 25 000 строк: когда станет больше 30 000, самые старые удаляются сами. Лист можно очищать руками (оставь первую строку с заголовками).
- Защита от мусора: один посетитель — не больше 15 пачек событий в минуту, всего — 3000 пачек в час. Сверх этого события молча отбрасываются.

## Часть 1в. Подключение сайта к серверу (T2.6)

После T2.6 сайт читает каталог **из твоей таблицы** и отправляет заказы в неё. Код подключения уже в репозитории, сайт публикуется сам.

1. **Только после части 1б, шаг 7** (новая версия веб-приложения): иначе сайт обратится к старому коду сервера.
2. Открой сайт `https://nhatrang-rynok.github.io/` с телефона или компьютера. Если видишь старый каталог-заглушку, обнови страницу жёстко (на компьютере Ctrl+F5, на телефоне закрой вкладку и открой заново): браузер мог закэшировать прежнюю версию.
3. Проверь: в каталоге те же 14 товаров, что в листе «Товары», контакты внизу главной — твои настоящие (из «Настроек»).
4. Измени цену товара в таблице (например, «Цена ₫» у манго) и обнови сайт: через пару минут (или сразу после **🛒 Рынок → Обновить сайт сейчас**) цена должна поменяться.
5. Оформи тестовый заказ на сайте (телефон `+84 000 000 000`, в комментарии «ТЕСТ»). Должно появиться: экран «Заказ № N-000X принят», строка в «Заказы», сообщение в Telegram. Потом поставь этому заказу статус «Отменён».
6. **Пока не проверишь пункты 3–5, ссылку никому не показывай и не публикуй.**

## Часть 2. Обновление кода (каждый раз, когда Claude поменял `apps-script/`)

Claude в каждом отчёте пишет раздел **«Как развернуть»**: какие файлы заменить, нужны ли новые свойства или разрешения и какую функцию запустить. Общая схема:

1. Таблица → **Расширения → Apps Script**.
2. Замени содержимое изменённых файлов (и добавь новые, если они есть): открыть файл → выделить всё → вставить из репозитория. Сохрани (Ctrl+S).
3. Если сказано запустить функцию (например `setup`): выбери её вверху и нажми **«Выполнить»**. Если просит разрешения — разреши.
4. Если сказано добавить свойство скрипта: ⚙️ → «Свойства скрипта» → «Изменить свойства скрипта» → «Добавить свойство».
5. **Выпусти новую версию в том же развертывании**: Развернуть → Управление развертываниями → ✏️ → «Версия»: «Новая версия» → «Развернуть».
6. Проверь `<адрес>?action=ping`.

## Часть 3. Если что-то не работает

| Симптом | Что проверить |
|---|---|
| `?action=ping` просит войти в Google или пишет «нет доступа» | В развертывании «Запуск от имени: Я» и «У кого есть доступ: Все» (Anyone). Изменить: Управление развертываниями → ✏️ |
| `?action=catalog` отвечает `{"ok":false,"error":"SERVER",…}` | Открой ☰ **«Выполнения»** (Executions) слева и найди запуск с ошибкой. Часто причина в том, что не выполнен `setup` или таблица, к которой привязан скрипт, не та. Скопируй текст ошибки в сессию |
| `{"ok":true,…,"products":[]}` | Лист «Товары» пуст или у товаров не стоит галочка «Показывать». Сделай **🛒 Рынок → Проверить таблицу**: там написано, что не так |
| Правка в таблице не видна на сайте | Подожди до 5 минут. Сразу: **🛒 Рынок → Обновить сайт сейчас**. Если и после этого нет, проверь лист «Ошибки» |
| Товара нет на сайте | Лист «Ошибки» и **🛒 Рынок → Проверить таблицу**: там указана строка и причина (нет цены, плохой ID, неверная категория) |
| Исправил код, а на сайте ничего не поменялось | Не выпущена новая версия развертывания (шаг 6) |
| После обновления снова просит разрешения | Это нормально, если в «Как развернуть» написано, что добавлены разрешения. Запусти любую функцию из редактора и подтверди |
| `SyntaxError: Identifier '…' has already been declared` при любом запуске | В двух файлах редактора лежит один и тот же код (или чужой код попал не в свой файл). Сверь начало каждого файла с таблицей в части 1б, шаг 1. Имя в ошибке подскажет файл-источник (`HEADER_COLOR_` → `Setup`), а `… @ Orders.gs` — куда он попал лишним |
| «У вас нет разрешения на вызов функции UrlFetchApp.fetch» (или `MailApp.sendEmail`) | Не выданы новые разрешения: запусти в редакторе функцию **`authorize`** (часть 1б, шаг 2). Из меню таблицы окно разрешений не показывается. Если `authorize` отработала без окна, а ❌ остались, в редакторе старый `appsscript.json` со строкой `oauthScopes`: замени его файлом из репозитория |
| Сайт не читает ответы сервера (`Failed to fetch`, CORS), а `?action=ping` в окне браузера показывает страницу **«Ошибка»** с текстом вроде «Нельзя выбрать числовой формат ячеек для столбца с заданным типом данных» | Скрипт делает всё, но в конце запуска Google выдаёт страницу ошибки вместо данных, а страница без заголовков CORS браузеру недоступна. С версии `2026-10-12.6` скрипт сам гасит такие ошибки оформления таблицы. Открой `<адрес>?action=ping` в окне инкогнито: должен показаться JSON с версией `.6` или выше. Если опять «Ошибка», пришли её текст |
| Гость видит «Не получилось отправить заказ», а заказ в таблице есть | Ответ сервера не дошёл до телефона. В версии `.4` сайт сам спрашивает у сервера (`orderStatus`) и покажет «Принят». Причину смотри в «Журнале»: событие «Заказ (сайт)» с текстом «ответ не получен (…)». Убедись, что выпущена новая версия веб-приложения и обновлён сайт (на телефоне перезагрузить страницу) |
| Лист «Журнал» пуст или в нём нет событий с сайта | События сервера (заказы, меню) пишутся всегда, события `Сайт` — только если в «Настройках» `log_events` включён, а сайт открыт не из заглушки. События уходят через 5 секунд после действия или при закрытии вкладки. Проверь, что выпущена новая версия веб-приложения |
| В «Уведомление» написано «Telegram не настроен (нужны TELEGRAM_BOT_TOKEN и TELEGRAM_CHAT_IDS)» | Не задано одно из свойств скрипта. `authorize` покажет, какое. `TELEGRAM_CHAT_IDS` заполняется через «🛒 Рынок → Найти chat_id Telegram» после того, как получатель нажал «Старт» у бота |
| Заказы появляются где-то внизу листа, а не под заголовком | Остались тестовые строки внизу, ниже тысячной строки (часть 1б, шаг 6, пункт 5). Удали их |
| Не знаю, какая версия кода работает | `<адрес>?action=ping` показывает `"version"`. Она должна совпадать с версией в начале `apps-script/Main.gs` на GitHub (`SCRIPT_VERSION_`) |
| Не приходят уведомления о заказах | **🛒 Рынок → Отправить тестовое уведомление**: в окне причина. Проверь свойства `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_IDS` и что получатель нажал «Старт» у бота. В листе «Заказы» в колонке «Уведомление» написан итог по каждому заказу, подробности в листе «Ошибки» |
| Заказ не записывается, гость видит «Не получилось отправить» | Лист «Ошибки»: там написано, чего не хватает (лист «Заказы» удалён или переименована колонка «Номер», «Телефон», «Состав»…). **🛒 Рынок → Первоначальная настройка** вернёт недостающее. Гость в это время может отправить заказ через WhatsApp кнопкой на сайте |
| Ошибка «Не найдена таблица» | Скрипт должен быть создан **из таблицы** (Расширения → Apps Script), а не отдельно. Запусти `setup` из редактора |
