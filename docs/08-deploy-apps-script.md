# Как развернуть Apps Script (инструкция для владельца)

Всё делается в браузере на компьютере. Командная строка не нужна. Названия пунктов даны для русского интерфейса Google, в скобках — английские.

Код лежит в репозитории, в папке `apps-script/`. Файл в репозитории = файл в редакторе. Открывать файлы на GitHub удобно так: открыть файл → кнопка **«Copy raw file»** (два квадратика над кодом) → вставить в редактор.

> Секреты (токен бота и т. п.) в репозитории не хранятся и в код не вставляются: только в **Свойства скрипта** (шаг «Свойства скрипта» ниже).

---

## Часть 1. Первая установка кода (T2.3)

### Шаг 1. Открыть редактор

1. Открой таблицу **«Мой рынок»** → **Расширения → Apps Script** (Extensions → Apps Script).
2. Слева вверху можно назвать проект, например «Рынок».
3. Слева ⚙️ **«Настройки проекта»** (Project Settings) → включи **«Показывать файл манифеста appsscript.json в редакторе»**.

### Шаг 2. Заменить файлы проекта

В списке файлов слева сейчас есть `Код.gs` (`Code.gs`) и, возможно, `index` (HTML). Нужно, чтобы остались только файлы из репозитория.

1. **`index`** (HTML-файл): наведи на него → ⋮ → **«Удалить»**. Он не нужен.
2. **`Код.gs`**: ⋮ → **«Переименовать»** → введи `Main` (без `.gs`). Выдели в нём весь текст (Ctrl+A) и вставь содержимое `Main.gs` из репозитория.
3. **`appsscript.json`**: открой, выдели всё, вставь содержимое `apps-script/appsscript.json`.
4. Добавь три файла: **«+» рядом с «Файлы» → «Скрипт»**, имя **без `.gs`**, вставь содержимое:
   - `Logic`
   - `Catalog`
   - `Setup`
5. Нажми 💾 (Ctrl+S). В списке файлов должно быть ровно: `Catalog`, `Logic`, `Main`, `Setup`, `appsscript.json`.

### Шаг 3. Первая настройка таблицы

1. Вверху в выпадающем списке функций выбери **`setup`** → **«Выполнить»** (Run).
2. Появится **«Требуется авторизация»** → **«Проверить разрешения»** → выбери свой аккаунт.
3. Экран **«Приложение не проверено Google»** нормален для своего скрипта: **«Дополнительные настройки» → «Перейти на страницу … (небезопасно)» → «Разрешить»**. Разрешения: таблица, меню, триггеры.
4. Дождись «Выполнение завершено». В таблице появятся листы **Товары, Категории, Настройки, Заказы, Позиции заказов, Ошибки**, пустой «Лист1» исчезнет, а вверху — меню **«🛒 Рынок»**. Появится окно «Настройка завершена» со сводкой (если не появилось, обнови страницу таблицы).

Повторный запуск `setup` безопасен: данные не стираются и не дублируются.

### Шаг 4. Загрузить примеры товаров

Каталог на сайте пока пустой. Загрузим 14 примерных товаров (фрукты и ром), чтобы проверить всю цепочку. Потом вы с Саней замените их настоящими.

1. На GitHub открой `content/descriptions/sample-products.csv` → **«Download raw file»** (значок загрузки справа над кодом). Файл сохранится на компьютер.
2. В таблице открой лист **«Товары»** → **Файл → Импорт → Загрузка** → выбери файл → **«Заменить текущий лист»** → **«Импортировать данные»**. Если таблица спросит про защищённый диапазон (заголовки), подтверди: это только предупреждение.
3. **🛒 Рынок → Первоначальная настройка**: вернёт флажки и выпадающие списки, которые импорт мог сбросить.
4. **🛒 Рынок → Проверить таблицу** → должно быть «Проблем не найдено. На сайте сейчас: товаров — 14, категорий — 2».

Фото у товаров пока нет, на сайте будет заглушка. Фото подключим в задаче T3.1.

### Шаг 5. Свойства скрипта (секреты)

Токен бота ты уже добавил. Проверь, что он на месте: ⚙️ **«Настройки проекта» → «Свойства скрипта»** (Script Properties): должно быть `TELEGRAM_BOT_TOKEN`. Остальные свойства (`TELEGRAM_CHAT_IDS`, `ALERT_EMAIL`) добавляются в части 1б.

### Шаг 6. Обновить веб-приложение (развертывание уже есть)

Веб-приложение у тебя уже развёрнуто, адрес менять не нужно. Нужно только выпустить **новую версию** в нём:

1. **«Начать развертывание» (Deploy) → «Управление развертываниями» (Manage deployments)**.
2. Выбери активное развертывание → ✏️ **карандаш** → **«Версия»: «Новая версия»** → **«Развернуть»**. Если попросит разрешения — разреши.
3. Проверь в браузере (подставь свой адрес, оканчивающийся на `/exec`):
   - `<адрес>?action=ping` → `{"ok":true,"time":"…"}`;
   - `<адрес>?action=catalog` → длинный текст JSON, в котором есть названия товаров («Манго», …).
   Если браузер просит войти в Google, в развертывании не выбрано «У кого есть доступ: Все» (см. ниже «Если что-то не работает»).
4. **Пришли в сессию Claude Code** слова «T2.3 готово» и, если проверка не прошла, текст ошибки или скриншот.

> ⚠️ **Не нажимай «Новое развертывание»** для обновлений: получится новый адрес, и сайт продолжит ходить по старому.
>
> Изменения кода без шага 6 на сайт **не попадают**: веб-приложение работает на зафиксированной версии. Меню и триггеры в таблице при этом сразу используют свежий код.

На сайт каталог и заказы подключаются в задаче T2.6 (адрес впишет Claude), после проверки приёма заказов (часть 1б).

## Часть 1б. Приём заказов и уведомления (T2.5)

Код приёма заказов добавлен в T2.4. Нужно обновить файлы, добавить свойства и проверить уведомления.

### Шаг 1. Обновить файлы

1. Таблица → **Расширения → Apps Script**.
2. Замени содержимое: **`Logic`**, **`Main`**, **`appsscript.json`**. (Остальные — `Catalog`, `Setup` — не менялись.)
3. Добавь два новых файла: **«+» рядом с «Файлы» → «Скрипт»**, имя без `.gs`:
   - `Orders`
   - `Notify`
4. Сохрани (Ctrl+S). В списке должно быть: `Catalog`, `Logic`, `Main`, `Notify`, `Orders`, `Setup`, `appsscript.json`.
5. **Новые разрешения.** В `appsscript.json` добавились два: «отправка запросов во внешние сервисы» (Telegram) и «отправка писем» (запасной канал). Выбери любую функцию (например, `setup`) → **«Выполнить»** → подтверди разрешения: «Проверить разрешения» → аккаунт → «Дополнительные настройки → Перейти → Разрешить».
6. Обнови страницу таблицы, чтобы в меню **«🛒 Рынок»** появились новые пункты.

### Шаг 2. Свойства скрипта

⚙️ **«Настройки проекта» → «Свойства скрипта» → «Изменить свойства скрипта»**. Токен бота (`TELEGRAM_BOT_TOKEN`) уже есть. Добавь:

| Свойство | Значение |
|---|---|
| `ALERT_EMAIL` | твоя почта: сюда придёт письмо, если Telegram не сработает |
| `TELEGRAM_CHAT_IDS` | можно не заполнять вручную, см. шаг 3 |

### Шаг 3. Получатели в Telegram

1. **Саня** и (если хочешь получать заказы тоже) **ты** открываете бота в Telegram по ссылке и нажимаете **«Старт»**.
2. В таблице: **🛒 Рынок → Найти chat_id Telegram**. Появится список тех, кто написал боту. Нажми **«Да»**, чтобы записать их chat_id в `TELEGRAM_CHAT_IDS` (если нужен только один человек, нажми «Нет» и добавь его chat_id вручную в свойство; несколько chat_id пишутся через запятую).
3. **🛒 Рынок → Отправить тестовое уведомление** → у каждого получателя в Telegram должно появиться «✅ Проверка связи». Если ❌, в окне написана причина (например, человек не нажал «Старт»).

### Шаг 4. Тестовый заказ

1. **🛒 Рынок → Создать тестовый заказ**. Окно покажет номер заказа и «Уведомление: ok». В Telegram придёт сообщение «🛒 Новый заказ …» с кнопками «Написать в WhatsApp», «Написать в Telegram», «Открыть таблицу».
2. В листе **«Заказы»** появилась строка (имя «ТЕСТ», статус «Отменён»), в **«Позиции заказов»** одна строка с отметкой «Отменён».
3. **Проверь защиту от формул.** В листе «Заказы» в ячейке «Телефон» должно быть `+84000000000` **без апострофа** и без превращения в число. Если ты видишь `'+84000000000` с апострофом, напиши об этом в сессию: правило записи текста надо будет поменять.
4. В «Свойства скрипта» появилось `ORDER_SEQ` (номер последнего заказа). Тестовый заказ занял номер N-0001; настоящие пойдут дальше (если хочешь начать с N-0001, удали строку тестового заказа и значение `ORDER_SEQ`).

### Шаг 5. Новая версия веб-приложения

**Развернуть → Управление развертываниями → ✏️ → «Версия»: «Новая версия» → «Развернуть»** (так же, как в части 1, шаг 6). Адрес не меняется. Проверь `<адрес>?action=ping`.

Сайт к заказам подключается в задаче T2.6. Напиши в сессию «T2.5 готово» и результаты шагов 3–4 (особенно проверку телефона без апострофа).

## Часть 2. Обновление кода (каждый раз, когда Claude поменял `apps-script/`)

Claude в каждом отчёте пишет раздел **«Как развернуть»**: какие файлы заменить, нужны ли новые свойства или разрешения и какую функцию запустить. Общая схема:

1. Таблица → **Расширения → Apps Script**.
2. Замени содержимое изменённых файлов (и добавь новые, если они есть): открыть файл → выделить всё → вставить из репозитория. Сохрани (Ctrl+S).
3. Если сказано запустить функцию (например `setup`): выбери её вверху и нажми **«Выполнить»**. Если просит разрешения — разреши.
4. Если сказано добавить свойство скрипта: ⚙️ → «Свойства скрипта» → «Изменить свойства скрипта» → «Добавить свойство».
5. **Выпусти новую версию в том же развертывании**: Развернуть → Управление развертываниями → ✏️ → «Версия»: «Новая версия» → «Развернуть».
6. Проверь `<адрес>?action=ping`.

## Часть 3. Если что-то не работает

| Симптом | Что проверить |
|---|---|
| `?action=ping` просит войти в Google или пишет «нет доступа» | В развертывании «Запуск от имени: Я» и «У кого есть доступ: Все» (Anyone). Изменить: Управление развертываниями → ✏️ |
| `?action=catalog` отвечает `{"ok":false,"error":"SERVER",…}` | Открой ☰ **«Выполнения»** (Executions) слева и найди запуск с ошибкой. Часто причина в том, что не выполнен `setup` или таблица, к которой привязан скрипт, не та. Скопируй текст ошибки в сессию |
| `{"ok":true,…,"products":[]}` | Лист «Товары» пуст или у товаров не стоит галочка «Показывать». Сделай **🛒 Рынок → Проверить таблицу**: там написано, что не так |
| Правка в таблице не видна на сайте | Подожди до 5 минут. Сразу: **🛒 Рынок → Обновить сайт сейчас**. Если и после этого нет, проверь лист «Ошибки» |
| Товара нет на сайте | Лист «Ошибки» и **🛒 Рынок → Проверить таблицу**: там указана строка и причина (нет цены, плохой ID, неверная категория) |
| Исправил код, а на сайте ничего не поменялось | Не выпущена новая версия развертывания (шаг 6) |
| После обновления снова просит разрешения | Это нормально, если в «Как развернуть» написано, что добавлены разрешения. Запусти любую функцию из редактора и подтверди |
| Не приходят уведомления о заказах | **🛒 Рынок → Отправить тестовое уведомление**: в окне причина. Проверь свойства `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_IDS` и что получатель нажал «Старт» у бота. В листе «Заказы» в колонке «Уведомление» написан итог по каждому заказу, подробности в листе «Ошибки» |
| Заказ не записывается, гость видит «Не получилось отправить» | Лист «Ошибки»: там написано, чего не хватает (лист «Заказы» удалён или переименована колонка «Номер», «Телефон», «Состав»…). **🛒 Рынок → Первоначальная настройка** вернёт недостающее. Гость в это время может отправить заказ через WhatsApp кнопкой на сайте |
| Ошибка «Не найдена таблица» | Скрипт должен быть создан **из таблицы** (Расширения → Apps Script), а не отдельно. Запусти `setup` из редактора |

## Часть 4. Резервная копия

Раз в месяц (или перед крупными изменениями): таблица → **Файл → Создать копию**. Код и так хранится в репозитории.
