# Спецификация серверной части (Google Apps Script)

Скрипт **привязан к таблице** (создаётся из таблицы: Расширения → Apps Script). Код в репозитории — в `apps-script/`. Владелец копирует его в редактор вручную (`08-deploy-apps-script.md`).

## Script Properties (секреты и служебные значения)

| Ключ | Кто задаёт | Описание |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | владелец | Токен от @BotFather |
| `TELEGRAM_CHAT_IDS` | владелец | chat_id через запятую (Саня, при желании владелец) |
| `ALERT_EMAIL` | владелец | Почта для запасных уведомлений и ошибок |
| `PHOTOS_FOLDER_ID` | `setup()` | ID папки «Фото товаров» (создаётся, если нет, **как подпапка той папки, где лежит таблица**) |

| `CATALOG_ERRORS_SIG` | скрипт | Отпечаток последнего набора проблем таблицы: одна и та же проблема пишется в «Ошибки» один раз |

## `doGet(e)`

- `action=catalog` → `getCatalog_()`; `action=ping` → `{ok, time}`; иначе → `{ok:false, error:"UNKNOWN_ACTION"}`.
- Любое исключение → `{ok:false, error:"SERVER"}` + запись в «Ошибки». Стек наружу не отдаём.

## Каталог и кэш

- `buildCatalog_()` читает «Категории», «Товары», «Настройки», «Позиции заказов» (последние `popular_days` дней).
- Колонки ищутся по заголовку. Если обязательный заголовок не найден — ошибка в «Ошибки», каталог отдаётся без этого поля или (для `ID`, `Название`, `Категория`, цены) пустым, с `ok:true` и сохранением прошлого кэша. Цель — сайт не падает из-за одной кривой правки.
- Строки валидируются по правилам из `04-google-sheet.md`.
- Ссылка на фото: если в `Фото` лежит ID файла (25+ символов `[A-Za-z0-9_-]`) или ссылка Диска — извлечь ID и превратить в `https://lh3.googleusercontent.com/d/<ID>`. Если это любая другая `https://` ссылка — отдать как есть.
- `version` = ISO-время сборки + `#` + первые 6 символов MD5 от JSON (`Utilities.computeDigest`).
- Кэш: `CacheService.getScriptCache()`, TTL 300 с. Ограничение 100 КБ на значение → JSON режется на куски по 30 000 символов (кириллица в кэше занимает 2–3 байта на знак, а предел — 100 КБ на значение): `cat_v1_meta` = `{parts}`, `cat_v1_0…N`. Читаем через `getAll`, если какого-то куска нет — пересобираем. Рядом (`cat_v1_good_*`, 6 часов) лежит копия «последнего хорошего» каталога: если в таблице сломали обязательные заголовки, сайт получает её, а не пустой каталог.
- `clearCatalogCache()` удаляет meta (без meta кэш считается пустым).

## `doPost(e)`

1. `JSON.parse(e.postData.contents)`. Не разобралось → `VALIDATION`.
2. `action === "order"` → `handleOrder_`. Иначе `UNKNOWN_ACTION`.

## `handleOrder_(body)`

Порядок важен:

1. Ловушка `website` не пустая → вернуть `{ok:true, orderNo:"N-0000"}`, ничего не писать.
2. `orders_enabled` выкл → `ORDERS_PAUSED`.
3. `validateOrder_(body, catalogIndex)` (чистая функция) → нормализованный заказ или ошибки (`VALIDATION`, `ITEM_UNAVAILABLE`). Каталог для проверки берётся из `getCatalog_()` (тот же кэш, цены актуальны в пределах 5 минут; при `ITEM_UNAVAILABLE` перед отказом пересобрать каталог без кэша и проверить ещё раз).
4. `LockService.getScriptLock().waitLock(20000)`:
   - идемпотентность: `CacheService` ключ `ord_<clientOrderId>` → если есть, вернуть сохранённый номер с `duplicate:true`;
   - лимиты: счётчики в кэше `rl_phone_<телефон>` (3 за 10 мин) и `rl_global_<час>` (60 в час) → `RATE_LIMIT`;
   - `ORDER_SEQ + 1` → `N-0001` (4 цифры, дальше растёт);
   - `appendRow` в «Заказы» и пачкой `setValues` в «Позиции заказов». Все пользовательские строки — через `sanitizeCell_` (префикс `'` для `= + - @`);
   - записать `ord_<clientOrderId>` в кэш на 6 часов, увеличить счётчики лимитов.
5. Снять блокировку.
6. `notifyOrder_` в try/catch: результат записать в колонку «Уведомление».
7. Вернуть `{ok:true, orderNo, total, duplicate:false}`.

## Уведомление в Telegram

`POST https://api.telegram.org/bot<TOKEN>/sendMessage`, `parse_mode: "HTML"`, `disable_web_page_preview: true`, на каждый chat_id из `TELEGRAM_CHAT_IDS`. `muteHttpExceptions: true`, проверять `ok` в ответе.

Текст (всё пользовательское — через `escapeHtml_`):

```
🛒 <b>Новый заказ N-0042</b>
📞 +79990000000 — предпочитает WhatsApp
👤 Ольга, комн. 512

• Манго — 2 кг × 90 ₽ = 180 ₽
• Ром Chill — 1 бут. 0,7 л × 650 ₽ = 650 ₽
<b>Итого ≈ 830 ₽</b>
🔞 Возраст подтверждён

💬 Манго поспелее
```

И `reply_markup` с inline-кнопками-ссылками: «Написать в WhatsApp» (`https://wa.me/79990000000`), «Написать в Telegram» (`https://t.me/+79990000000`), «Открыть таблицу» (URL таблицы).

Если Telegram не ответил `ok` ни для одного chat_id → письмо на `ALERT_EMAIL` с тем же текстом (без HTML) + строка в «Ошибки».

## `syncPhotos()`

- Папка из `PHOTOS_FOLDER_ID`. Перебрать файлы-изображения (`image/*`).
- Имя без расширения в нижнем регистре = ID товара (`FR-001.JPG` → `fr-001`). Если файлов с одним ID несколько — берём последний изменённый.
- Для найденного товара: если в `Фото` пусто или там другой ID файла → вписать ID файла, открыть доступ «все, у кого есть ссылка — читатель».
- Файлы, которым не нашлось товара, — перечислить в «Ошибках» (не чаще раза в сутки на файл).
- В конце, если были изменения, — `clearCatalogCache()`.
- Запуск: пункт меню и триггер по времени каждые 10 минут.

## `setup()` (запускается владельцем один раз и после обновлений схемы)

Идемпотентна: повторный запуск ничего не ломает и не дублирует.

- Создать недостающие листы и заголовки; закрепить первую строку; защитить заголовки (режим «предупреждение»).
- Выпадающие списки: `Категория` (диапазон ID категорий), `Наличие`, `Статус`, `Связь`. Флажки: `Показывать`, `18+`, `Хит`.
- Условное форматирование «Заказов» по статусу.
- Начальные данные: «Категории» — только если лист пуст; «Настройки» — добавляются недостающие ключи, существующие значения не трогаются.
- Колонки ищутся по заголовку: переставленные колонки остаются на местах, удалённые обязательные дописываются в конец, свои колонки не мешают.
- *(T3.1)* Создать папку «Фото товаров» (если нет `PHOTOS_FOLDER_ID`) внутри папки, где лежит таблица (`DriveApp.getFileById(ssId).getParents()`), открыть к ней одной доступ по ссылке (читатель), сохранить ID. Доступ ко всей родительской папке и к таблице не менять.
- Установить триггеры (удалив старые с тем же обработчиком): `handleEdit` (по правке таблицы). *(T3.1)* `syncPhotos` (каждые 10 минут).
- Часовой пояс таблицы выставляется в `Asia/Ho_Chi_Minh`, в свойства записывается `SPREADSHEET_ID`.
- Лист по умолчанию («Лист1», «Sheet1») удаляется, только если он пустой.
- В конце показать окно со сводкой: что создано, ссылка на папку с фото, чего не хватает в Script Properties.

## `handleEdit(e)` — установленный триггер

Если правка на листах «Товары», «Категории» или «Настройки» → `clearCatalogCache()`. Если на «Товарах» и не в колонке «Обновлено» → проставить дату в «Обновлено» у изменённых строк. Функция **не** должна называться `onEdit`, иначе она запустится дважды (как простой и как установленный триггер).

## Меню «🛒 Рынок» (`onOpen`)

- Обновить сайт сейчас → `clearCatalogCache()`
- Подтянуть фото → `syncPhotos()` *(T3.1)*
- Проверить таблицу → прогнать валидацию, показать список проблем
- Отправить тестовое уведомление → `testNotify()`
- Найти chat_id Telegram → `findTelegramChatIds()` (вызывает `getUpdates`, показывает найденные chat_id с именами и по согласию сразу записывает их в `TELEGRAM_CHAT_IDS`)
- Создать тестовый заказ → `menuTestOrder()` (настоящий заказ с телефоном `+84 000 000 000`: номер, строки в таблице, сообщение в Telegram; сразу помечается «Отменён»)
- Первоначальная настройка → `setup()`

На телефоне меню Apps Script недоступно. Поэтому всё, что нужно Сане, работает автоматически через триггеры (кэш, фото). Меню нужно владельцу на компьютере.

## Тестируемость

`Logic.gs` не обращается к сервисам Google. Тесты на Node (`tests/logic.test.js`) загружают файл через `vm.runInContext` (`tests/gas-loader.js`) и проверяют: нормализацию телефонов (`8 999…`, `+7 (999)…`, `+84 90…`, мусор), валидацию заказа (шаг, минимум, 18+, длины, дубли ID), расчёт рублёвой цены из донгов, «популярное», экранирование HTML, защиту от формул.

## Как это проверяется без Google

- `tests/logic.test.js` — вся чистая логика, включая сверку проверки телефона с сайтом и сверку каталога, собранного из `content/descriptions/sample-products.csv`, с заглушкой сайта `catalog.sample.json`.
- `tests/apps-script.test.js` — `Setup.gs`, `Catalog.gs` и `Main.gs` на подставных сервисах (`tests/gas-fakes.js`: таблица в памяти, кэш с лимитом 100 КБ, свойства, триггеры). Проверяется, что повторный `setup()` ничего не дублирует и не стирает, что кэш и «последний хороший» каталог работают, что ошибки пишутся один раз.
- Чего тесты не покажут: настоящую выдачу разрешений, поведение веб-приложения под анонимным доступом и вид таблицы на телефоне. Это проверяет владелец по списку в `docs/08-deploy-apps-script.md`.

## Приём заказа: как это устроено на самом деле (T2.4)

- `doPost` принимает JSON из тела запроса (до 30 000 знаков). Не JSON, пустое тело или не объект — `VALIDATION`; `action` не `order` — `UNKNOWN_ACTION`. Любое неожиданное исключение — `SERVER` без подробностей, подробности (без токена) в лист «Ошибки».
- Ловушка `website` проверяется первой и ничего не пишет. Затем пауза (`ORDERS_PAUSED`) и проверка заказа по каталогу из кэша. Если кэш говорит «товара нет», каталог перед отказом перечитывается из таблицы.
- Под `LockService` (до 20 с): повтор по `clientOrderId` (кэш на 6 часов) возвращает прежний номер с `duplicate:true` и не считается в лимитах; лимиты (3 с телефона за 10 минут, 60 в час всего) → `RATE_LIMIT`; номер = максимум из счётчика `ORDER_SEQ` и самого большого номера в листе «Заказы» плюс один; строка в «Заказы» пишется по заголовкам колонок. Без колонок «Номер», «Создан», «Телефон», «Состав», «Сумма ₽» заказ не принимается (`SERVER` и запись в «Ошибки»), чтобы не потерять данные.
- «Позиции заказов» пишутся после того, как заказ принят; сбой здесь не отменяет заказ, а попадает в «Ошибки».
- Уведомление отправляется после снятия блокировки. Итог пишется в колонку «Уведомление»: `ok`, `ok, но не всем: …`, `ошибка Telegram: …; письмо отправлено` и т. п. Если не дошло ни одно сообщение, идёт письмо на `ALERT_EMAIL`. Сообщение длиннее 3900 знаков уходит простым текстом без разметки.
- Токен бота скрывается (`scrubSecrets_`) в любом тексте, который попадает в лист «Ошибки», окна и итоги уведомлений.
- Текст, который пишется в ячейки, проходит `sanitizeCell_`: значения, начинающиеся с `= + - @`, получают ведущий `'`. **Нужно проверить в настоящей таблице** (пункт в `docs/08`, часть 1б): комментарий `=HYPERLINK("http://x","a")` должен показываться как обычный текст, а телефон — как `+84000000000` без апострофа.

## Разрешения и версия кода

- Окно выдачи разрешений Google показывает **только при запуске функции из редактора**. Меню таблицы и веб-приложение его не показывают: они просто падают с ошибкой «нет разрешения на вызов функции …». Поэтому есть функция `authorize()` (в `Notify.gs`): её запускают вручную после каждого добавления разрешений, она же проверяет таблицу, запросы в интернет, почту, триггеры и свойства.
- Ошибки вида «нет разрешения» в статусах уведомлений и окнах меню сопровождаются подсказкой «выберите функцию authorize» (`permissionHint_`).
- `SCRIPT_VERSION_` в `Main.gs` меняется при каждом изменении файлов в `apps-script/` (формат `ГГГГ-ММ-ДД.N`). Версия видна в ответе `?action=ping` и в окне `authorize`.
- У каждого `.gs` файла вторая строка начинается с ` * <Имя>.gs — `: по ней владелец сверяет, что вставил нужный код. Тест следит и за этим, и за тем, чтобы имена верхнего уровня не повторялись между файлами.
