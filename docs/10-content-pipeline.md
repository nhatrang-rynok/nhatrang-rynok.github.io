# Конвейер сбора контента

Цель — получить список товаров (кандидатов), согласовать его с Саней, а затем наполнить таблицу названиями, описаниями, предупреждениями и фото.

```
YouTube-ролики ──► расшифровки (.txt) ──► Claude: выжимка ──► content/candidates.csv
                                                                     │
                                                    лист «Кандидаты» в таблице
                                                                     │
                                         Саня: «Берём? цена, где купить»
                                                                     │
                                Claude: описания и предупреждения → content/descriptions/
                                                                     │
                                 владелец/Саня вставляют в лист «Товары» + Саня снимает фото
```

## Шаг 1. Расшифровки YouTube (делает владелец, без командной строки)

В облачной среде Claude YouTube недоступен (ошибка 403), поэтому тексты приносит владелец.

**Способ через интерфейс YouTube (рекомендую):**
1. Найти на YouTube 10–15 роликов по запросам: «что привезти из Вьетнама», «что купить в Нячанге», «рынок Чо Дам», «вьетнамская аптека что купить», «вьетнамский кофе какой купить». Брать ролики последних 2–3 лет, по возможности с разными авторами.
2. Открыть ролик на компьютере → под видео развернуть описание → кнопка **«Показать текст видео»** (Show transcript). Справа появится расшифровка.
3. В панели расшифровки (⋮) можно отключить отметки времени. Выделить весь текст мышью → скопировать.
4. Вставить в Блокнот и сохранить как `<любое-короткое-имя>.txt`. **Первой строкой** вставить ссылку на ролик и его название.
5. Загрузить файлы в репозиторий через GitHub: папка `content/transcripts/` → **Add file → Upload files** → перетащить файлы → Commit. Или просто прикрепить файлы в чат сессии Claude.

**Альтернатива:** вставить ссылку на ролик в Gemini или NotebookLM и попросить «выпиши все товары, которые советуют купить, с ценами и комментариями». Результат сохранить в `.txt` так же. Это быстрее, но менее точно.

## Шаг 2. Выжимка кандидатов (делает Claude, задача T3.4)

Claude читает `content/transcripts/*.txt` и создаёт `content/candidates.csv` (UTF-8, разделитель `,`):

| Колонка | Пример |
|---|---|
| `name` | Ром Chill (Чилл) |
| `category` | alcohol |
| `mentions` | 7 (во скольких роликах упомянут) |
| `quotes` | «все везут ром Chill с кокосом…» (1–2 короткие цитаты) |
| `price_hint_vnd` | 150 000 (если называли в ролике) |
| `notes` | Есть варианты: кокосовый, обычный |
| `sources` | имена файлов расшифровок |

Правила: объединять синонимы и транслитерации (Чо Дам / Чо Дамм / Cho Dam); сортировать по `mentions`; лекарства — только безрецептурные (рецептурные помечать `notes: рецептурное — не берём`); алкоголь помечать 18+.

## Шаг 3. Согласование с Саней

1. Владелец открывает `candidates.csv` на GitHub → **Download raw file** → в таблице лист «Кандидаты» → **Файл → Импортировать → Загрузить** → «Вставить строки в текущий лист».
2. Саня с телефона заполняет: `Берём?` (Да/Нет/Позже), `Цена закупки ₫`, `Где купить`, `Комментарий Сани`. Можно добавлять свои строки — Саня лучше знает, что реально спрашивают.
3. Позиции с «Да» идут в каталог.

## Шаг 4. Описания и предупреждения (Claude, задача T3.5)

Владелец выгружает лист «Кандидаты» (Файл → Скачать → CSV) и прикладывает его в сессию. Claude для каждого «Да» готовит строку для листа «Товары» в `content/descriptions/products-<дата>.csv` с колонками ровно как в листе «Товары»:

- `ID` по схеме: `fr-` фрукты, `al-` алкоголь, `sw-` сладости, `cf-` кофе, `sv-` сувениры, `ph-` аптека + трёхзначный номер.
- `Коротко` — до 80 символов: вкус или назначение.
- `Описание` — 2–4 предложения, до 600 символов, простыми словами: что это, какой вкус или для чего, фасовка, как везти и хранить (например: «Плотная пластиковая бутылка, в багаж можно» — только если это точно так). Без превосходных степеней и медицинских обещаний.
- `Предупреждения` — из шаблонов `11-warnings-and-legal.md`. Не выдумывать: если шаблона нет — пусто и пометка в отчёте.
- `Единица`, `Шаг` — по смыслу (фрукты на вес — `кг`, шаг 0.5).
- `Цена ₫` — из колонки Сани. Рублёвую цену считает таблица.
- `Где куплено` — из колонки Сани.

Владелец импортирует CSV в лист «Товары» (Файл → Импортировать → «Добавить строки в текущий лист»). Саня проверяет тексты и цены.

## Шаг 5. Фото (Саня)

Инструкция для Сани в `12-operator-guide.md`. Требования:

- Своё фото, сделанное на рынке или в аптеке, — гость видит, что получит.
- Квадрат 1:1 или с запасом по краям (сайт обрезает до квадрата по центру).
- Дневной свет, нейтральный фон, товар целиком, по возможности с подсказкой размера (рука, монета).
- Для упаковок — лицевая сторона с читаемым названием. Для лекарств — упаковка, по которой гость узнает товар в аптеке.
- Имя файла = ID товара: `fr-001.jpg`. Положить в папку «Фото товаров» на Диске (из приложения «Google Диск»: + → Загрузить → выбрать фото → потом переименовать).
- Чужие фото с сайтов магазинов **не брать**. Стоки (Unsplash, Pexels, Pixabay) — только как временная заглушка, с проверкой лицензии каждого файла и записью источника в `content/photo-sources.md`.

## Шаг 6. Обновление

Цены меняются — Саня правит `Цена ₫` (рубли пересчитаются) или `Цена ₽`. Сезон закончился — `Наличие` = «Сезон закончился». Новый товар — новая строка + фото.
