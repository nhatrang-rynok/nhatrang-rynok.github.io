# CLAUDE.md: правила для Claude Code в этом репозитории

Прочитай этот файл целиком перед любой задачей. Потом прочитай `ROADMAP.md` и документы, которые указаны в задаче.

## Проект в двух словах

Мобильный сайт-каталог для русскоязычных гостей отеля в Нячанге: фрукты, ром, сладости, кофе, сувениры и обычные лекарства из аптеки. Гость собирает корзину и оставляет телефон, заказ уходит в Google Таблицу, а оператору (Сане) приходит сообщение от Telegram-бота. Оплаты на сайте нет.

## Кто пользователь

- **Владелец репозитория** — программист (Python, ML), но **командной строкой не пользуется**. Все команды (git, тесты, сборка) запускаешь ты сам. Инструкции для него пиши только для графического интерфейса: куда нажать и что вставить.
- **Гости** — русскоязычные, часто 40–50+ лет, сидят с телефона на лежаке, иногда на слабом интернете.
- **Саня** — оператор. Правит Google Таблицу с телефона, в коде не разбирается.

## Структура репозитория

```
site/                  статический сайт (публикуется на GitHub Pages)
  index.html
  css/app.css
  js/*.js              обычные ES-модули, без сборки
  config.js            URL веб-приложения Apps Script и резервные контакты
  data/catalog.sample.json   заглушка каталога для режима без бэкенда
  img/                 иконки, заглушки фото, иконка PWA
apps-script/           зеркало кода Google Apps Script (развёртывает владелец вручную)
  appsscript.json
  *.gs
tests/                 тесты на Node без зависимостей (node --test); tests/e2e/ — проверки в браузере (*.e2e.mjs)
tools/                 вспомогательные скрипты: картинки превью и иконки, Lighthouse, axe
package.json           только для тестов: "type": "module", зависимостей нет
.github/workflows/     деплой site/ на GitHub Pages
content/               сбор контента: расшифровки, кандидаты, тексты
docs/                  документация (не публикуется как сайт)
```

## Жёсткие правила

1. **Язык интерфейса — русский.** Цены показываем в рублях (₽) со знаком «≈», потому что они ориентировочные.
2. **Сначала мобильная версия.** Проверяй на ширине 360–390 px. Базовый шрифт ≥ 17–18 px, кнопки и зоны нажатия ≥ 48 px, контраст по WCAG AA.
3. **Сайт без фреймворков и без сборки.** Только HTML, CSS и ванильный JS (ES-модули). Никаких npm-зависимостей в `site/`. Весь JS вместе — не больше ~30 КБ в сжатом виде (gzip; без сжатия около 70 КБ), см. D72.
4. **Не делаем:** оплату, регистрацию и личные кабинеты, отзывы и оценки от посетителей, поддержку Max, обмен валют. Не добавляй это даже «на будущее».
5. **Секретов в репозитории нет.** Токен бота, chat_id, email и ID таблицы хранятся только в Script Properties в Apps Script. Репозиторий публичный. В тестах токен бота только фиктивный (`123456789:AAFake…`): это проверяет `tests/no-secrets.test.js`.
6. **Персональные данные гостей** (телефоны, имена, номера комнат) никогда не попадают в репозиторий, логи коммитов и тестовые фикстуры. В тестах используй только явно фиктивные номера вроде `+84 000 000 000` или `+7 000 000-00-00`.
7. **Цены и наличие задаёт только таблица.** Сервер пересчитывает сумму заказа сам и не доверяет ценам из браузера.
8. **Контакты-заглушки:** телефон и WhatsApp `+84 000 000 000`, Telegram `@primer_operator`. Реальные значения владелец потом впишет в лист «Настройки».

## Apps Script: как с ним работать

Владелец разворачивает Apps Script **вручную**: копирует файлы из `apps-script/` в редактор. Поэтому:

- Каждый `.gs` файл должен быть самодостаточным для копирования: одно имя файла в репозитории соответствует одному файлу в редакторе.
- Все `.gs` файлы делят **одну глобальную область видимости**: импортов нет, имена функций и констант должны быть уникальными. Вспомогательные функции заканчивай символом `_` (`normalizePhone_`), тогда их не видно в списке запуска и через `google.script.run`.
- Среда выполнения V8. Не используй синтаксис, которого нет в V8 Apps Script: ES-модули, `import` и `export`.
- **После любого изменения в `apps-script/`** допиши в итоговый отчёт (и в описание коммита) раздел **«Как развернуть»**:
  - какие файлы заменить или добавить в редакторе;
  - нужны ли новые Script Properties;
  - появились ли новые разрешения (scopes), то есть нужна ли повторная авторизация;
  - нужно ли запускать какую-то функцию вручную (например `setup`);
  - напоминание: **Развернуть → Управление развертываниями → карандаш → Версия: «Новая версия» → Развернуть**. URL при этом не меняется. **Новое развертывание не создавать.**
- При каждом изменении файлов в `apps-script/` увеличивай `SCRIPT_VERSION_` в `Main.gs` (`ГГГГ-ММ-ДД.N`): владелец проверяет по `?action=ping`, какой код работает. Первая строка каждого `.gs` — `/**`, вторая — ` * <Имя>.gs — описание` (на это опирается инструкция и тест).
- Явного списка `oauthScopes` в `appsscript.json` нет (D68): Google определяет разрешения по коду. Если в коде появился новый сервис Google (например, `DriveApp`), в «Как развернуть» обязательно напиши: **запустить в редакторе функцию `authorize`** (меню и веб-приложение окно разрешений не показывают) и **заменить `appsscript.json` в редакторе**.
- Любое событие, которое оператору полезно видеть, пиши в лист «Журнал» через `logEvent_(уровень, событие, подробности, {order, visitor})`; в `doGet`/`doPost`/триггерах запись происходит сама (`withFlush_`), в пунктах меню — через `logNow_`. Не пиши в журнал персональные данные гостя (правило 6).
- Подробная инструкция — `docs/08-deploy-apps-script.md`. Если процесс поменялся, обнови её.
- Чистую логику (валидация телефона, пересчёт цены, «популярное», рекомендации) держи в функциях без вызовов `SpreadsheetApp` и других сервисов, чтобы её можно было тестировать на Node (`tests/`). В тестах загружай `.gs` через `vm` и подставляй заглушки сервисов.

## Сайт: как работать

- Режим без бэкенда: если `API_URL` в `site/config.js` пустой, сайт читает `data/catalog.sample.json`, а отправку заказа имитирует (с задержкой, затем показывает экран успеха с номером `TEST-0001`). Этот режим должен работать всегда: на нём тестируем вёрстку.
- Маршрутизация через hash (`#/c/fruits`, `#/p/fr-001`, `#/cart`, `#/checkout`, `#/done/N-0001`). У GitHub Pages нет SPA-фолбэка.
- Корзину храни в `localStorage` (обёрнутом в try/catch), каталог кэшируй там же: сначала показываем кэш, потом обновляем.
- Проверяй вёрстку через Playwright: Chromium уже установлен, `executablePath: '/opt/pw-browsers/chromium'`, вьюпорт 390×844. Скриншоты клади в scratchpad, а не в репозиторий.

## Процесс работы над задачей

1. Найди задачу в `ROADMAP.md` (например `T1.3`) и прочитай документы из её поля «Читать».
2. Сделай задачу полностью, в рамках критериев приёмки. Не расширяй объём: заметил что-то за рамками — запиши в `docs/open-questions.md` или в отчёт.
3. Прогони тесты (`node --test`, без указания папки: в Node 22 `node --test tests/` не работает) и, если менял сайт, сквозные проверки в браузере: `node tests/e2e/catalog.e2e.mjs <папка для скриншотов>` (Playwright, свой статический сервер поднимается сам).
4. Отметь задачу в `ROADMAP.md` как `[x]`. Если менялся контракт API или схема таблицы, обнови `docs/05-api.md` и `docs/04-google-sheet.md`.
5. Сделай коммит. Сообщение на русском: что сделано и зачем. Если есть изменения Apps Script — раздел «Как развернуть».
6. В итоговом ответе пользователю: что сделано, как проверить (по-человечески, через браузер или таблицу), и раздел «Как развернуть», если менялся Apps Script.

## Чего нельзя

- Создавать новое развертывание Apps Script или менять `API_URL` без явной просьбы.
- Добавлять платные сервисы, внешние трекеры и аналитику без решения в `docs/decisions.md`.
- Копировать фото товаров с чужих сайтов. Только фото Сани или заглушки.
- Писать медицинские советы. Предупреждения — только общая справка с припиской (см. `docs/11-warnings-and-legal.md`).
